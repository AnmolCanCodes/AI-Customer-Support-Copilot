# Support Escalation Policy

## Purpose

The escalation policy defines when a customer issue should be transferred from regular customer support to a support manager or specialized team.

Support agents should attempt to resolve standard questions using the company's support documentation before escalating an issue.

## When to Escalate

A support issue should be escalated when:

* The issue falls outside the documented company policies.
* A customer requests an exception to a standard policy.
* A refund request is outside the normal 14-day refund period.
* A billing issue involves a suspected duplicate charge that cannot be resolved by the standard billing process.
* A customer reports a serious account access problem.
* A technical issue cannot be resolved using the available troubleshooting information.
* The customer has already contacted support multiple times about the same unresolved issue.
* A support manager's approval is required.

## Refund Exceptions

Refund requests submitted after the standard 14-day refund period require support manager review if the customer believes there are exceptional circumstances.

Regular support agents should not promise approval for an exception.

The customer should be informed that the request will be reviewed by a support manager.

## Billing Escalations

Billing issues should be escalated when the support team cannot determine the cause of an unexpected charge.

The support agent should collect relevant information such as:

* Account email
* Transaction date
* Transaction amount
* Payment reference
* Description of the billing problem

This information should be included when escalating the issue.

## Account Access Issues

Issues involving unauthorized account activity, suspected account compromise, or inability to access an account may require escalation to the appropriate account or security team.

Support agents should not disclose sensitive account information to an unverified customer.

## Technical Issues

Technical problems should first be checked against the available troubleshooting documentation.

If the documented troubleshooting steps do not resolve the issue, the case may be escalated to the technical support team.

The escalation should include a clear description of the problem and the troubleshooting steps already attempted.

## Repeated Customer Contact

If a customer contacts support multiple times about the same unresolved issue, the issue should be reviewed for escalation.

The support agent should check previous support interactions before escalating the case.

## Manager Approval

Some actions require approval from a support manager.

Examples include:

* Refund exceptions outside the standard refund period
* Exceptions to documented company policies
* Special billing adjustments
* Other actions specifically requiring management approval

Support agents should not guarantee an exception before receiving the required approval.

## Escalation Information

When escalating an issue, the support agent should provide:

* Customer's account email
* Summary of the customer's request
* Relevant transaction or subscription information
* Steps already taken
* Reason for escalation

Providing complete information helps the receiving team resolve the issue efficiently.
